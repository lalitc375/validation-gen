# +k8s:validateError

## Description
Specifies a custom validation error message to be returned when the validation rule fails. This tag allows for more descriptive and user-friendly error messages than the default ones generated by the system.

## Scope
`Field`

## Supported Go Types
Any Go type, in conjunction with a validation rule tag (`+k8s:validation:maxLength`, `+k8s:validation:pattern`, `+k8s:cel`, etc.).

## Payload
A string representing the custom error message.

## Stability
**Alpha**

## Usage

### Field
```go
type MyObject struct {
    // The name must be between 1 and 10 characters long.
    // +k8s:validation:maxLength=10
    // +k8s:validateError="name must not exceed 10 characters"
    Name string `json:"name"`
}
```
This tag is used to provide a more specific and helpful error message when a validation rule is violated.

## Migrating from Handwritten Validation

When migrating from handwritten validation logic, you can use the `+k8s:validateError` tag to preserve custom error messages that were previously part of your manual validation code. Instead of returning a generic error, you can provide a specific message that better explains the validation failure.

For example, if your old validation logic for a field was:
```go
if len(obj.Name) > 10 {
    allErrs = append(allErrs, field.Invalid(fldPath.Child("name"), obj.Name, "name must not exceed 10 characters"))
}
```
You can replace this with declarative validation tags:
```go
// +k8s:validation:maxLength=10
// +k8s:validateError="name must not exceed 10 characters"
Name string `json:"name"`
```
This ensures that the user receives the same informative error message as before.

## Detailed Example: Custom Error for Port Number Range

This example demonstrates how to use `+k8s:validateError` to provide a clear error message when a port number is outside the valid range.

### 1. Define the Tag in `types.go`
Apply the `+k8s:cel`, `+k8s:validation:minimum`, `+k8s:validation:maximum`, and `+k8s:validateError` tags to the `Port` field in the `MyObject` struct.

**File:** `pkg/apis/example/v1/types.go`
```go
type MyObject struct {
    // Port must be a valid IANA service port number (1-65535).
    // +k8s:validation:minimum=1
    // +k8s:validation:maximum=65535
    // +k8s:validateError="port must be between 1 and 65535"
    Port int `json:"port"`
}
```

### 2. Update Handwritten Validation
In the handwritten validation function for `MyObject`, the explicit check for the port range can be removed or marked as covered.

**File:** `pkg/apis/example/v1/validation/validation.go`
```go
func ValidateMyObject(obj *example.MyObject, fldPath *field.Path) field.ErrorList {
    allErrs := field.ErrorList{}

    // Original handwritten validation for Port range (example):
    // if obj.Port < 1 || obj.Port > 65535 {
    //    allErrs = append(allErrs, field.Invalid(fldPath.Child("port"), obj.Port, "port must be between 1 and 65535"))
    // }

    // After adding validation tags, this logic is handled declaratively.
    // If kept for migration, mark the error as covered:
    if obj.Port < 1 || obj.Port > 65535 {
        allErrs = append(allErrs, field.Invalid(fldPath.Child("port"), obj.Port, "port must be between 1 and 65535").MarkCoveredByDeclarative())
    }

    return allErrs
}
```
By using `+k8s:validateError`, the API provides a clear and specific error message when the `Port` field validation fails, improving usability.

## Test Coverage

To test the `+k8s:validateError` tag, you should create a test case that triggers the validation rule and then verify that the resulting error message matches the custom message you specified.

### Example: Custom Error Message for a Pattern Validation

**File:** `pkg/apis/example/v1/types.go`
```go
type MyStruct struct {
    // The username must start with a letter.
    // +k8s:validation:pattern=`^[a-zA-Z]`
    // +k8s:validateError="username must begin with a letter"
    Username string `json:"username"`
}
```

**Test Case:**
```go
// Create an object with an invalid username that violates the pattern.
invalidObj := &example.MyStruct{Username: "123-user"}

// In your test, you would call the validation function for MyStruct.
// The test should assert that the validation returns an error,
// and that the error message contains the custom text.

// Hypothetical test structure:
errs := validateMyStruct(invalidObj)
if len(errs) == 0 {
    t.Errorf("expected validation error, but got none")
} else {
    found := false
    for _, err := range errs {
        if strings.Contains(err.Error(), "username must begin with a letter") {
            found = true
            break
        }
    }
    if !found {
        t.Errorf("expected error message to contain 'username must begin with a letter', but got: %v", errs)
    }
}
```
This test ensures that your custom error message is correctly applied and returned to the user, providing a better experience than a generic pattern mismatch error.
